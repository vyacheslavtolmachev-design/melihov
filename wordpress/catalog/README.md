# Данные каталога

`varieties.tsv` — перечень сортов питомника. Источник правды для импорта в WordPress.

Разобран из файла заказчика «СОРТА САЖЕНЦЕВ.docx»: 12 культур, 102 сорта. Разбор сверен с
контрольными числами самого документа («Всего сортов» по каждой культуре и общий итог).
Опечатка исходника «Яблона» исправлена на «Яблоня». Йошта в документе заявлена культурой без сортов —
термин заводится, записей под ним пока нет.

## Колонки

| Колонка | Что это |
| --- | --- |
| `culture` | Слаг культуры: `apple`, `columnar-apple`, `pear`, `cherry`, `sweet-cherry`, `felt-cherry`, `plum`, `peach`, `apricot`, `currant`, `gooseberry`, `raspberry`, `josta` |
| `title` | Название сорта без культуры: «Флорина», а не «Яблоня Флорина» |
| `slug` | `{культура}-{транслит названия}`. Префикс обязателен: «Натали» есть и у смородины, и у войлочной вишни, «Чемпион» — у яблони и черешни |
| `ripening` | `summer` / `autumn` / `winter` |
| `region` | `middle` / `chernozem` / `south` |
| `rootstock` | `seed` / `semi-dwarf` / `dwarf` |
| `price_retail`, `price_wholesale` | Цены в рублях, целое число |
| `wholesale_min` | Опт от, штук |
| `sapling_age` | Свободный текст: «Двухлетка» |
| `availability` | `in_stock` / `preorder` / `sold_out`. Пусто = `in_stock` на витрине |
| `excerpt` | Краткое описание для карточки, 1–2 предложения |
| `planting_rules` | Схема посадки, глубина, полив |

Заполнены только `culture`, `title` и `slug` — остальное приходит от заказчика. Пустая колонка не
ошибка: витрина показывает «по запросу» вместо цены, пустые характеристики в таблицу не попадают,
а фильтр без значений скрывается целиком.

## Как дозаполнить

Файл открывается в Excel и Google Sheets как таблица с разделителем «табуляция». Дозаполните нужные
колонки, сохраните обратно в TSV в UTF-8 и прогоните импорт — он обновит существующие записи по
слагу, не создавая дублей.

**Слаг менять нельзя**: по нему живёт адрес карточки `/catalog/{slug}` и связь с уже загруженными
фотографиями. Новый слаг = новая запись, старая останется висеть.

## Импорт

```sh
docker compose run --rm --entrypoint sh wp-cli /import-catalog.sh
```

С флагом `--prune` дополнительно удаляются записи `variety`, которых нет в файле.

Что кому принадлежит: файл владеет всеми своими колонками, включая `excerpt` — пустая колонка
стирает краткое описание в базе. Полный текст описания (`post_content`) и загруженная фотография
сорта правятся только в админке, импорт их не трогает. Поэтому длинные тексты пишите в редакторе
WordPress, а не в TSV.

## Фотографии

Фото сорта становится его обложкой (featured image) и вытесняет с карточки иллюстрацию и общий кадр
культуры.

1. Положите файлы в `inbox/` в корне репозитория. Имя файла — название сорта: `Флорина.jpg`,
   `ГолденДелишес.jpg`. Если название есть у нескольких культур (Натали, Чемпион, Киргизская),
   добавьте культуру: `Черешня Чемпион.jpg`. Подойдёт и слаг: `apple-florina.jpg`. Родовое имя
   культуры годится и для уточнённой: `Вишня Натали.jpg` — войлочная вишня, `Яблоня Арбат.jpg` —
   колоновидная яблоня. Порядок слов в культуре не важен (`Яблоня_Колоновидная_Валюта.jpg`),
   «ё» и «э» читаются как «е», опечатки «Яблона» и «Яюлоня» понимаются. Если заказчик называет сорт иначе,
   чем в `varieties.tsv` («Персик Ананасный» при «Ананасовом» в каталоге), сверьте кадр и
   допишите синоним в `ALIASES` в начале скрипта — файлы в `inbox/` не переименовываем.
2. `python3 tools/photos/ingest.py` сопоставит файлы с сортами, срежет сплошную рамку, если снимок
   в неё вписан, ужмёт кадр до 1600 px и положит в `photos/{slug}.jpg`, а строку — в `photos.tsv`.
   Исходники в `inbox/` остаются, их удаляют руками; папка в `.gitignore`. С `--dry-run` скрипт
   только покажет, что куда пойдёт.
3. В `photos.tsv` уточните `alt` — что на кадре: «Яблоня Флорина — плоды на ветке».
4. Импорт в WordPress:

```sh
docker compose run --rm --entrypoint sh wp-cli /import-photos.sh
```

Импорт идемпотентный: вложение помечено слагом и хешем файла. Новый файл для того же сорта заменяет
прежнее фото и удаляет его из медиатеки. Иллюстрации и загруженные руками вложения не трогаются,
а `import-illustrations.sh` не ставит иллюстрацию поверх фото.
